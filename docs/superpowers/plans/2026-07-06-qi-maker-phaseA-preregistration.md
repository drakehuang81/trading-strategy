## 0. 為什麼先做 Phase A(而不是直接買數據)

- Vendor 實際定價(2026-07-06 查):tardis.dev Academic **$350/月**、Solo **$700/月**(Perpetuals)。比口頭估計($100-300)貴——**買之前必須先有免費證據**。
- **關鍵洞察**:雖然精確的 maker 排隊模擬需要 L2,但「**最悲觀成交假設**」(掛單只在成交價**嚴格穿過**掛價時才算成交)只需要 **L1 quotes + 全部成交印**——這兩者在免費檔案庫齊備(bookTicker + aggTrades,2023-05-16→2024-03-30)。
- 證據不對稱性(如實登記):trade-through 成交是**逆向選擇最重的子集**(價格正穿過你才成交);at-touch 排隊成交(需 L2 才能模擬)的品質只會更好。因此 Phase A 的每筆淨利**低估**真實 maker 經濟——**Phase A 亮眼 ⇒ 強證據買數據;Phase A 全滅 ⇒ 報告缺口大小,由缺口決定是否仍值得買**。
- qi 秒級 IC 0.37 是全 program 唯一驗證過的資訊量;本 Phase 量測的是它的**可捕獲量級**,這是 IC 沒回答的問題。

## 2. 量測設計(鎖定)

- **qi(t)** = (bid_qty − ask_qty)/(bid_qty + ask_qty) @ L1,每**整秒**取樣(該秒最後一筆 tick)。
- **固定門檻**(不用當日分位數,避免同日內生):多方訊號 qi ≥ **+0.6**;空方 qi ≤ **−0.6**(對稱)。
- **悲觀 maker 週期(多方;空方鏡像)**:訊號秒 t 且無持倉 → 掛買單於 best_bid(t);**成交規則**:未來 **10s** 內第一筆 aggTrade 成交價 **< best_bid(t)** 才算成交(成交價 = 我們的掛價);10s 無穿越 → 撤單(零成本)。成交後於 t_fill + **h** 以 taker 出場,出場價 = 當時 **best_bid**(賣單打到買一,再度悲觀)。
- **主 horizon h = 10s**(唯一判定 horizon);{1, 5, 30, 60}s 僅描述性。
- **費用**:maker 2.0bps 進 + taker 5.0bps 出 = **7bps RT**(不假設 BNB 折扣)。
- 每筆淨利(bps)= (exit_bid − entry_price)/entry_price × 1e4 − 7(空方鏡像)。
- 統計:逐日聚合(日均每筆淨利、日總淨利、成交率、逆向選擇 = fill 時 mid 相對掛價的位移);跨 20 個日均值做 t-stat。

## 3. 判定(鎖定)

| 判定 | 條件 | 後果 |
|------|------|------|
| **DEAD** | 主 horizon 每筆淨利均值 ≤ 0 | **不買數據**;qi maker 回到自錄時間線,且屆時需重新設計(L1 悲觀界已否定 taker 出場式 maker) |
| **WEAK** | 淨利 > 0 但 t < 2 或 正收益日 < 60% | 同上不買;自錄數據滿後再驗 |
| **PROCEED** | 淨利 > 0 且 t ≥ 2 且 ≥60% 天為正 | **Phase B**:向使用者提交購買提案(tardis 實際方案+登記草案),批准後才花錢 |

無論結果,report 須含:缺口分析(悲觀界距離損益兩平多少 bps——這決定 at-touch 排隊成交「可能」補回多少)、兩側(多/空)分拆、費用敏感度(BNB 折扣 1.8+4.5bps 情境,描述性)。

**本 Phase 不設終局條款**——它是購買決策的評估工具,不是機制存廢判定;機制存廢由(若進行的)Phase B 以 L2 精確模擬 + 四道 gate + 複製窗判定。但 Phase A 結果如實寫回,DEAD/WEAK 即省下 $350-700/月。
